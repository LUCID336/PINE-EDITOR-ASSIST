# Market Feature Protocol v1
Eine kanonische Feature-Engine pro Build, verschiedene Presentation-Adapter. Beispiel: `examples/feature_core.pine` enthält Bibliotheksentwurf; `examples/hybrid_indicator.pine` ist ein selbständiges Referenzscript mit Human-/AI-Modus. Kein Import erforderlich. Bei Produktion Bibliothek nach Prüfung veröffentlichen und Version pinnen oder Code aus einer Quelle generieren. Separate Pane/Overlay-Scripts möglich, Parität über gleiche Fixtures absichern.

Event: `schema_version`, `build`, `config_id`, `symbol` (Exchange:TICKER), `timeframe`, `bar_open_ms`, `bar_close_ms`, `confirmed`, `quality`, `features`. Im Beispiel event time = Barende, tatsächliches `received_at` und `available_at` werden extern separat gesetzt. `config_id` kodiert effektive Inputs; in Produktion Hash aus vollständiger Konfiguration. Dedup-Key = build + config_id + symbol + timeframe + bar_open_ms; Revisionen separat speichern, nicht blind überschreiben. Zeitbasierte Bars für diese v1-Implementierung vorausgesetzt. Fehlende Werte JSON null, nicht "NaN", null nicht 0. Relative Einheiten: RSI 0–100; ATR und EMA in Quote-Preis; RVOL dimensionslos; HTF close in Quote-Preis. Datenqualität `READY` oder `MISSING`, pro Feature zusätzliche Source-/Quality-Metadaten im Feature-Store, mit Feed/Venue und Beobachtungszeit. Keine Vermischung von Barclose mit Empfangszeit oder HTF-Ursprungszeit. `confirmed` ist nur Chart-Barbestätigung; HTF-Wert im Beispiel separat um einen HTF-Bar versetzt. Bei fehlendem/unbestätigtem/stale Input keine Aktion.

Pipeline: TradingView alert → HTTPS endpoint (kein Credential im Alert; Zugriff über abgesicherte Infrastruktur und Anbieterregeln, Rate Limits) → schnelle Annahme + dauerhafte Queue → JSON Schema + Business validation → dedup → append-only store → reconcile mit CSV und externen Marktfeeds → Feature Store → AI Agent → unabhängige Risk Gate / Paper Mode. Webhook darf nicht als garantierte Delivery oder historische Replay-API behandelt werden. Alerts werden in der UI eingerichtet, nach Änderungen neu angelegt. Webhook-Regeln, HTTPS, 2FA und aktuelle Timeout/Port-Limits im Support nachschlagen. Keine ungeprüfte Orderausführung. Reconcile fehlende Bars, späte/duplizierte Events, out-of-order, Versionswechsel, Symbolwechsel, DST, Feed-Revisions. Authentifizierung und Secret Management außerhalb Pine. Archivierung gemäß Datenlizenz.

AI-Auswertung: 1) Source-/Freshness-Check, 2) Marktregime, 3) HTF-/LTF-Kontext, 4) unabhängige Evidenz (nicht mehrere korrelierte Oszillatoren als drei Beweise), 5) Bull/Base/Bear mit Trigger und Invalidation, 6) NO TRADE wenn unvollständig, 7) nur validierte Regeln für Entry/SL/TP/Risk. Konfidenzscore nur kalibriert, sonst als heuristischer Score beschriftet. Feature Store muss Point-in-time-Abfragen unterstützen.
