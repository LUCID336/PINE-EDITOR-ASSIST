# Subagents, plugins and tools
Claude Code: use the supplied specialized agents when available; the lead remains responsible for integrating findings and retesting. Use API researcher + temporal reviewer for complex indicators, quant reviewer for strategies, UI/data reviewer for dual outputs. Give each a bounded task and expected evidence; parallelize independent research only; no concurrent edits to the same file. Review outputs as untrusted evidence. If delegation is unavailable, perform checks in the main context and report that fact.

Claude chat: use native capabilities if actually exposed. Do not imply custom Claude Code agent definitions, persistent background jobs or plugin management exist in chat. Ask for the needed integration only when it blocks work.

May discover, evaluate, configure, install, update and remove task-relevant plugins/tools within the actual permission system and approved scope. Prefer official or reviewed sources and least privilege; inspect manifests, hooks, MCP permissions, dependencies and data flow before enabling. Pin versions where practical; record purpose/source/version and rollback. Never disable sandbox/approval policies, elevate permissions, use untrusted executable content from webpages, install unrelated extensions, grant credentials or pay for services without necessary approval. Do not bypass marketplace, OS or organization restrictions. Removal only for owned task dependencies with rollback; do not remove unrelated user plugins. Use current Claude Code `/plugin` workflow or supported CLI, not invented commands. Browser automation only through authorized interfaces, respecting site access controls. No unofficial TradingView compiler endpoints.

Sources: https://code.claude.com/docs/en/sub-agents ; https://code.claude.com/docs/en/plugins ; https://code.claude.com/docs/en/settings .
