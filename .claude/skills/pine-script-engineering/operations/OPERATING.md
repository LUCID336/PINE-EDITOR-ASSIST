# Operational contract
- Work inside the authorized project; keep original code and unrelated files intact. Version outputs and record changes. Never overwrite user edits silently.
- Choose simple, robust code; typed inputs, explicit state, bounded collections, no unnecessary requests or drawing churn. Validate version and qualifiers. Compute history-dependent series consistently. Distinguish pivot detection time, signal time, and plotted location.
- Use the six V3 audit perspectives: sources/API, language/version, temporal/data, strategy/statistics, UI/payload, release/regression. Each records finding, repair, retest and evidence; reopen affected gates. For simple changes scale depth, not truthfulness. For complex changes use up to six full improvement passes, stop early if all gates pass or no progress, report why. Do not claim six loops if not performed.
- Human: clear visual hierarchy, minimal defaults, optional detail toggles, separate oscillator pane if useful, accessible colors and labels. AI: versioned numeric feature IDs, units, observation timestamps, symbol/feed/timeframe, confirmed/provisional, missing as null, dedup and quality. Same core calculations; verify parity.
- Test statuses: PASS requires observed evidence; FAIL requires finding; NOT RUN for unavailable tests; NOT APPLICABLE only with reason. Separate static validation from TradingView compilation/runtime/backtests.
- No automatic live orders, broker connections, payments, publication or sharing private data; obtain separate authorization for those actions. Default NO TRADE when evidence inadequate. Market advantage is a hypothesis, not a guarantee.
