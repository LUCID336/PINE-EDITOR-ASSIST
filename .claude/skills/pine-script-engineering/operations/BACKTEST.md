# Backtest and strategy validation
1. Define hypothesis, instrument/feed, sessions, timeframe, date range, inputs, execution timing, long/short, position sizing, initial capital and benchmark before evaluating results.
2. Use official TradingView Pine Editor and Strategy Tester when accessible and authorized. Record actual compile result and strategy settings; use realistic commissions, slippage, tick/lot sizing, margin and fill assumptions. Avoid synthetic-chart execution assumptions, hidden future knowledge, unconfirmed HTF values and pivot backdating. Record Bar Magnifier availability, order-on-close, calc-on-every-tick, order-fill recalculation and their historical/realtime implications.
3. If Strategy Tester unavailable, implement a clearly labeled external model only with real supplied/licensed data or explicitly synthetic fixtures. External simulation does not establish exact TradingView parity; record data provenance, timezone, missingness, execution ordering and divergences. Do not fabricate trades, metrics or datasets.
4. Split chronologically (train/validation/test), keep final test untouched until selection, log all tried variants, test regime sensitivity and cost stress. Walk-forward where sample allows; compare simple benchmark. Guard against survivorship, data leakage, selection bias and overfitting. Evaluate number of trades, net returns, max drawdown, expectancy, profit factor, exposure, risk-adjusted metric with definition; show sample uncertainty. Do not optimize purely for Sharpe or win rate.
5. Report configuration, data coverage, costs, metrics, trades/equity evidence, assumptions, out-of-sample and forward-test status, failure cases and limitations. Keep paper trading separate from live execution. Never interpret training fixtures as market proof.
Official docs: https://www.tradingview.com/pine-script-docs/concepts/strategies/ and https://www.tradingview.com/pine-script-docs/concepts/repainting/.
